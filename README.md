# Yuanease Data Sphere 案例库

**Yuanease Data Sphere（数据星球）** 是 Yuanease 桌面应用里「实体模型」功能的技术品牌：把企业散落在 Excel、CSV 和数据库里的表格，整理成统一的业务实体、关系与指标，让数字员工按同一套口径回答业务问题。

本仓库收录 11 个可以从零复现的行业案例。每个案例都包含：

- `data/`：CSV 表格，体积在几 MB 以内；多数案例取自公开的真实数据或厂商样例库，由 `prepare/` 下的脚本从原始文件生成；
- `README.md`：从新建资料库、上传表格、构筑实体模型、审核发布到问数的逐步教程，配 Yuanease 实拍截图；
- `gold.yaml`：实体、唯一标识列、关系与指标的金标，有主外键的数据集直接从原始建表语句推导；
- `questions.yaml`：10–16 道问答题，标准答案由题目里的 SQL 在 `data/` 上独立算出；每题的 `source` 写明出处：出自竞品或开源项目公开教程、示例查询的题（「原作者题」），或案例作者按数据补出的题（「自补题」）；
- `prepare/`：从原始公开数据（或固定随机数种子）重新生成 `data/` 的脚本；真实数据案例另有直接从原始文件重算标准答案的脚本。

选数据源的优先顺序：竞品厂商自己公开的演示数据 > 开源社区的语义层 / 本体项目数据 > 政府与公共机构的开放数据，许可没核实到原文的不用。数据档位的含义：**真实测量**是企业、研究机构或监管机构公开的真实业务记录；**厂商样例**是软件厂商为教程公开发布的样例库（公司与数据虚构，但出自第三方、可从原始文件逐字节复现）；**虚构**是本仓库自建的数据。每个案例的原始文件地址、许可、sha256、改动与复现方法见 [PROVENANCE.md](PROVENANCE.md)。

源自其他厂商公开教程的案例，只复现其业务场景与问题清单，并在案例 README 开头注明出处；教程文字与截图均为本仓库自行撰写与拍摄。

## 怎么用

1. 安装并登录 Yuanease 桌面应用（0.8.7 或更高版本）。
2. 克隆本仓库，或下载 ZIP 后解压。
3. 打开任意案例目录，按 `README.md` 的步骤操作；每个案例约 25–40 分钟，以各案例 README 开头写的「预计用时」为准。
4. 用下面的命令核对标准答案（需要 Python 3.9+ 与 PyYAML）：

```bash
python3 -I tools/casekit.py answers cases/01-supply-chain-network --check
```

## 评测口径

- **首扫加权准确率**：上传表格后点一次「构筑实体模型」，中途员工提问一律回答「不知道，请你按数据自己判断。」，把得到的实体模型与 `gold.yaml` 比对。实体、唯一标识列、关系、指标四项分别计算 F1，按 0.3 / 0.2 / 0.3 / 0.2 加权。
- **问答准确率**：模型审核发布后，逐题提问；回答中包含标准答案的全部取值（数字允许 0.5% 相对误差）判为正确。主指标只算原作者题，自补题单独报告；题库在实跑前冻结，`BANK.md` 记录每个 questions.yaml 的 sha256。
- **独立复现**：由没有参与制作的智能体，只拿到本仓库与 Yuanease 安装包，照 README 从零完成全部步骤。

各案例的实测成绩见对应 README 的「实测记录」。

### 实测汇总（2026-10-22，Yuanease Dev 0.8.7，三档模型 deepseek-v4.1-flash-1017）

问答由没有参与制作的智能体逐题判分。主指标只算「真实测量」与「厂商样例」两档，虚构档单独列出。

| 档位 | 案例 | 首扫加权准确率中位数 | 原作者题 | 案例作者补的题 |
|---|---|---|---|---|
| 真实测量 | 06、07、08、09、11 | 0.771 | 9/10 | 43/45 |
| 厂商样例 | 01、02、03、05、10 | 0.828 | 41/43 | 29/30 |
| **主指标（以上两档合计）** | 10 个案例 | **0.801** | **50/53 = 94.3%**（Wilson 95% 区间 0.85–0.98） | 72/75 = 96.0% |
| 虚构 | 04 | 0.971 | 4/4 | 9/10 |

- 每个案例的首扫分项、问答逐题结果与说明见各案例 README 的「实测记录」。
- 实体与唯一标识列在多数案例接近满分；扣分主要在关系与指标：员工多半只起草计数类指标，合计、比率类指标要在第 4 步说明口径或审核后补；08 员工把小表都挂在订单上，关系分偏低。
- 问答错题集中在三类：口径分歧（例如「机动车」是否包含轮胎、配件）、员工改去读本机原始文件被拒后没有给出结论、以及按另一张表计数。
- 01–05 在 10-20/21 用旧模型跑过一次，成绩写在各案例「实测记录」的对照行；09 沿用 10-21 用同一模型、同一安装包跑的结果。

## 目录结构

```
cases/<编号-名称>/
  README.md        逐步教程与实测记录
  data/            案例数据（上传这里的全部文件）
  gold.yaml        实体模型金标
  questions.yaml   问答题、计算 SQL 与标准答案
  images/          教程截图
  prepare/         数据生成脚本
tools/casekit.py   核对标准答案、核验金标、给回答打分
tools/test_casekit.py  判分规则自检（标准答案必须判对、改错数字必须判错）
```

## English summary

**Yuanease Data Sphere** turns scattered spreadsheets and database tables into a governed entity model (entities, keys, relationships, metrics) that AI workers use to answer business questions consistently. This repository contains 11 reproducible manufacturing, supply-chain and quality cases. Data sources are ranked by provenance: real operational records published by companies, researchers or regulators (cases 06–09, 11), public sample databases from software vendors such as Snowflake, Microsoft and Google Malloy / Looker (01–03, 05, 10), and one synthetic case (04); every source file is pinned with its URL, license and sha256 in PROVENANCE.md and can be regenerated byte-for-byte. Each case ships CSV data, a step-by-step tutorial with screenshots of the Yuanease desktop app, a gold-standard entity model derived from the source schema, and 10–16 questions whose answers are computed independently with SQL (`tools/casekit.py`); questions taken from the original vendor or open-source tutorials are reported separately from questions written for this repository. Cases derived from other vendors' public tutorials reproduce only the business scenario and question list; all text and screenshots are original. Code is MIT; tutorials, gold files and the synthetic parts of case 04 are CC BY 4.0; third-party data keeps its original license (see THIRD_PARTY_NOTICES.md).

# 案例 10 · 定制加工订单的五类指标

> 场景参考自 dbt Semantic Layer 快速入门（<https://docs.getdbt.com/guides/sl-qs>）讲解的五类指标：简单、比率、累计、派生、转化。
> 原教程的 jaffle-shop 数据许可未核实，本案例改用自建的机加工订单数据；教程文字、截图均为本仓库自行撰写与拍摄。

## 场景

一家机加工厂按客户图纸接单：先报价，成交后下订单，生产后交付。经营会上要看五类指标：订单金额与订单数（简单）、按期交付率（比率）、按月累计订单金额（累计）、毛利与毛利率（派生）、报价成交率（转化）。

## 你将完成

1. 新建资料库并上传 5 张表格。
2. 让数字员工「BI 分析师」构筑实体模型：识别实体、唯一标识列、表与表之间的关系，以及常用指标。
3. 审核员工识别出的关系并发布。
4. 用自然语言问业务问题，与下方标准答案逐题核对。

预计用时 30–40 分钟（构筑 8–15 分钟，问数每题 1–3 分钟）。

数据要点：

- 「报价单」的成交订单号只在成交时有值，指向「订单」。
- 「是否按期」只对已交付订单有值：实际交付日期不晚于承诺交期为「是」。
- 计算订单金额时通常要排除「已取消」订单。

数据来源与改动：全部由 `prepare/build_data.py` 以固定随机数种子生成，内容虚构。

## 操作步骤

### 0. 准备

- 安装并登录 Yuanease 桌面应用（版本 0.8.7 或更高）。
- 下载本仓库：`git clone <仓库地址>`，或在仓库页面下载 ZIP 后解压。本案例的数据在 `cases/10-order-metric-types/data/`。

### 1. 新建资料库

左侧导航进入「资料库」，点右上角「新建资料库」。名称填「案例10 订单五类指标」（如果账号里已经有同名资料库，可以在名称后加上日期或姓名缩写以示区分），描述可选填，范围与权限保持默认，点「创建资料库」。

![新建资料库](images/1-new-kb.jpg)

### 2. 上传表格

在新资料库里点右上角「添加」→「表格」，点「点击上传、拖拽或粘贴文件」，选中 `data/` 目录下全部 5 个文件，再点「索引 5 个文件」。之后对话框会回到空的上传状态，这是正常的：关掉对话框，资料库的内容列表里每个文件显示「就绪」（通常 10–60 秒）即完成。如果账号里有同名资料库或同名线程，请从资料库列表的卡片进入自己建的那个。

![选择表格](images/2-upload.jpg)

### 3. 构筑实体模型

切到「实体模型」页签，点「构筑实体模型」。向导默认选中全部表格，保存位置为新建文件夹「实体模型」，由「BI 分析师」构筑。保持默认，点「开始构筑」。

![构筑向导](images/3-build-wizard.jpg)

构筑在后台运行，通常需要 8–15 分钟，可以关掉窗口。进度窗口可能较长时间停在「解析表格」，属正常现象。

- 页头右侧的「● 1」可以打开「智能体工位」，查看这次构筑的进度；
- 回到「实体模型」页签时，如果看到「有一次构筑还没完成。」和「继续构筑」按钮，点它只是重新打开这次构筑的进度窗口，不会重新开始。

![构筑进行中](images/4-build-running.jpg)

### 4. 回答员工的提问

开始几分钟后，员工会把从数据里看不出业务含义的地方集中问你一次（问题内容每次可能不同）。提问卡片「数字员工需要你的输入」在页头「● 1」打开的「智能体工位」里（标着「需人工 · 待输入」的卡片，点开即可），也可以从左侧线程里标着「待输入」的这次构筑进入。**不回答，构筑会一直停着。**了解业务就直接回答，可以参考上方「数据要点」；不确定就回答「不知道，请你按数据自己判断。」，本案例的实测成绩按这个回答得到。填好后点「提交并继续」。

![员工提问](images/5-employee-question.jpg)

如果希望员工一次建得更完整，可以把下面这段参考回答整段粘贴进去（它说明了本案例的业务含义与常用指标口径；本页「实测记录」的首扫成绩是在不提供这段说明的情况下得到的）：

> 这是机加工厂的订单数据。报价成交后才有订单，报价单的成交订单号指向订单；是否按期只对已交付订单有值；统计订单金额通常排除已取消订单。常用指标：订单金额合计、订单数、订单成本合计、按期交付率 = 按期交付订单数（是否按期 = 是）÷ 已交付订单数、报价成交率 = 成交报价数（是否成交 = 是）÷ 报价数。

### 5. 审核关系并发布

构筑完成后，回到资料库的「实体模型」页签，点「去审核」。左侧逐条列出员工识别出的关系，每条给出关联字段，以及「智能体推断」或「用户确认」（第 4 步里你确认过的）标签；有的关系还会附取值重合率，没有附时按关联字段判断，默认都是「暂不确定」。员工会给实体起业务名称，可能与表名不完全一样（例如「货运」显示为「货运单」），按关联字段判断即可。关系较多时，列表要往下滚动才能看全。按下面的规则逐条点「成立」或「不成立」：

- 取值重合 100%、关联字段名称对得上的关系，以及标注「智能体推断」、字段名称明显对应的关系：点「成立」。
- 重合率明显偏低、或你从业务上判断不对应的关系：点「不成立」。

员工识别出的关系条数每次可能略有不同：下方「期望结果」里有、但这次没有出现的关系，不用手动补，跳过即可（首扫成绩会相应扣分）。审核页只确认关系；员工起草的指标目前以计数类为主，「期望结果」里的合计、比率类指标可能没有生成，这不影响后面问数（员工会按原始表计算并说明口径）。页面下方的「试问」与「待解问题」是员工的自检记录，可以只看不处理。审核时在对话框内部滚动，发布前不要点对话框外的灰色区域（会直接关闭对话框，已点的选择会丢失）。全部处理后点右下角「发布」，看到「实体模型已发布」即完成。如果发布后发现有关系没确认，可以在「实体模型」页签切到「实体」，点开实体，在右侧「关系」页签里逐条点「确认」或「不成立」。

![审核关系](images/6-review.jpg)

![发布完成](images/7-published.jpg)

### 6. 问数

在资料库顶部点「智能问答」。输入框开头有一个「针对 案例10 订单五类指标 回答：」的前缀块，先点一下前缀块右侧，再输入问题，按回车发送。会话页头的「未选择目录」提示不影响问数，可以忽略。逐题输入下方表格里的问题，与标准答案核对。

员工有时（不是每次）会先弹卡请你确认指标口径（例如「订单数 = 按行计数」）：确认无误就选中「确认…」或「认可…」这一项，再点「提交并继续」。之后如果弹出「修改实体模型」的授权卡（员工要把你的确认写回模型），选「允许一次」。如果弹出的授权卡只有「始终允许」（例如员工想在本机执行脚本），可以点「拒绝」，员工会改用资料库里的表格作答。

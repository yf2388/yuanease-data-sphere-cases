# 案例 08 · 仓库停运后的订单影响与替代仓库

> **数据档位：真实测量**。数据是一家全球芯片制造商提供的出库物流数据（Brunel University London「Supply Chain Logistics Problem Dataset」，CC BY 4.0；来源说明见论文 Dzalbs & Kalganova 2020 第 4 节）：9,215 张订单、19 个仓库的产能与成本、仓库可供产品等 7 张表；本仓库只译了表名列名，取值未改。出处、许可、原始文件 sha256 与复现方法见 [PROVENANCE.md](../../PROVENANCE.md)。

> 场景参考自 Palantir 博客「Building with Palantir AIP」系列的配送中心起火剧本（Data Tools、Logic Tools 两篇）；旧版用自建虚构的泵阀企业数据。本版改用公开的真实出库物流数据，仓库「停运」是题目里的假设情景，原始数据没有停运记录。
> 问答题 q11–q13 的问题意图取自上述剧本的步骤（找受影响订单与客户、按产品列缺口、看哪些正常仓库能补上），出处逐题写在 questions.yaml 的 source；教程文字、截图均为本仓库自行撰写与拍摄。

## 场景

一家芯片制造商通过 19 个仓库向客户发货。某天的 9,215 张订单记下了每张订单从哪个仓库、经哪个港口、由哪家承运商、按哪种服务方式发出。供应链经理要预案：如果某个仓库停运，哪些订单、客户、产品受影响；这些产品还有哪些仓库能供；这些仓库每天能处理多少订单。

## 你将完成

1. 新建资料库并上传 7 张表格。
2. 让数字员工「BI 分析师」构筑实体模型：识别实体、唯一标识列、表与表之间的关系，以及常用指标。
3. 审核员工识别出的关系并发布。
4. 用自然语言问业务问题，与下方标准答案逐题核对。

预计用时 30–40 分钟（构筑 8–15 分钟，问数每题 1–3 分钟）。

数据要点：

- 「订单」一行一张订单，订单编号唯一（原始写法带一位小数，例如 1447296446.7）；全部订单都是 2013-05-26 这一天的；仓库代码（原列名 Plant Code）是发货仓库。
- 「仓库产能」「仓库成本」都是一个仓库一行：日处理订单能力是每天最多能处理的订单数，单位仓储成本以美元/件计。
- 「仓库可供产品」列出每个仓库能供应哪些产品（仓库代码 + 产品编号唯一），判断停运后能否由别的仓库替代就看这张表；「VMI客户」列出只能由指定仓库服务的专属客户；「仓库港口」列出仓库能用的起运港。
- 「运费费率」按承运商、起运港、目的港、服务方式与重量区间给出费率，与订单是区间匹配，不是普通的一对多；原始数据里有 3 行完全重复，照原样保留。服务方式 DTD 是门到门、DTP 是门到港、CRF 是客户自提运费。

数据来源与改动：取自 Brunel University London 在 figshare 发布的 Supply chain logisitcs problem.xlsx（文件名拼写照原样）；7 个工作表各存成一个 CSV，只译表名、列名，订单日期写成 YYYY-MM-DD。规则见 `prepare/build_data.py` 文件头；`prepare/truth_from_raw.py` 直接从原始 xlsx 重算全部标准答案，并核对订单表与原始工作表逐行相同。

## 操作步骤

### 0. 准备

- 安装并登录 Yuanease 桌面应用（版本 0.8.7 或更高）。
- 下载本仓库：`git clone <仓库地址>`，或在仓库页面下载 ZIP 后解压。本案例的数据在 `cases/08-supply-disruption/data/`。

### 1. 新建资料库

左侧导航进入「资料库」，点右上角「新建资料库」。名称填「案例08 仓库停运影响」（如果账号里已经有同名资料库，可以在名称后加上日期或姓名缩写以示区分），描述可选填，范围与权限保持默认，点「创建资料库」。

![新建资料库](images/1-new-kb.jpg)

### 2. 上传表格

在新资料库里点右上角「添加」→「表格」，点「点击上传、拖拽或粘贴文件」，选中 `data/` 目录下全部 7 个文件（选文件前主按钮叫「开始索引」且不可点，选中后变成「索引 7 个文件」），点它。之后对话框会回到空的上传状态，这是正常的：关掉对话框，资料库的内容列表里每个文件显示「就绪」（通常 10–60 秒）即完成；页面上的构筑提示写的表格数会随就绪逐步增加，等它与上传的文件数一致再进入下一步。如果账号里有同名资料库或同名线程，请从资料库列表的卡片进入自己建的那个。

![选择表格](images/2-upload.jpg)

### 3. 构筑实体模型

切到「实体模型」页签，点「构筑实体模型」。向导默认选中全部表格，保存位置为新建文件夹「实体模型」，由「BI 分析师」构筑。保持默认，点「开始构筑」。

![构筑向导](images/3-build-wizard.jpg)

构筑在后台运行，可以关掉窗口。进度窗口可能较长时间停在「解析表格」，属正常现象。

- 页头右侧的「● 1」可以打开「智能体工位」，查看这次构筑的进度；
- 回到「实体模型」页签时，如果看到「有一次构筑还没完成。」和「继续构筑」按钮，点它只是重新打开这次构筑的进度窗口，不会重新开始。

![构筑进行中](images/4-build-running.jpg)

### 4. 回答员工的提问

开始几分钟后，员工会把从数据里看不出业务含义的地方集中问你一次（问题内容每次可能不同）。提问卡片「数字员工需要你的输入」在页头「● 1」打开的「智能体工位」里（标着「需人工」的卡片，状态为「待输入」或「等待输入」，点开即可），也可以从左侧线程里标着「待输入」的这次构筑进入；构筑进度窗口变成「员工在等你处理」时，窗口里的「查看过程」按钮也能直接进入。**不回答，构筑会一直停着。**了解业务就直接回答，可以参考上方「数据要点」；不确定就回答「不知道，请你按数据自己判断。」，本案例的实测成绩按这个回答得到；独立复现或想与实测成绩对比时，统一这样回答。填好后点「提交并继续」。

实测中员工问了五点：订单表一行是一张订单还是一个产品行；服务方式 CRF 指什么、为什么运费费率表里没有 CRF；PLANT01、PLANT07、PLANT10 各有两个港口是主港加备选港还是同时使用；仓库可供产品表里有一行仓库代码 CND9 不在其他表里，是外部仓还是录入错误（这是原始数据里的真实情况）；日处理订单能力按订单数还是订单行数算。 了解业务时可以这样回答：「一行是一张订单；CRF 是客户自行安排运输，不按费率计费；两个港口都可以用；CND9 原样保留，不在仓库产能表里；日处理订单能力按订单数计。」也可以直接粘贴后面的参考回答。

![员工提问](images/5-employee-question.jpg)

如果希望员工一次建得更完整，可以把下面这段参考回答整段粘贴进去（它说明了本案例的业务含义与常用指标口径；本页「实测记录」的首扫成绩是在不提供这段说明的情况下得到的）：

> 订单一行一张订单，仓库代码是发货仓库；仓库产能、仓库成本都是一个仓库一行，下游各表的仓库代码都关联到它们。仓库可供产品是仓库与产品的对应（判断停运后谁能替代），VMI客户是仓库的专属客户，仓库港口是仓库能用的起运港；运费费率按承运商、港口、服务方式与重量区间匹配，不和订单直接相连。常看：订单数、订购数量合计、重量合计、延迟发货订单数、日处理订单能力。

### 5. 审核关系并发布

构筑完成后，回到资料库的「实体模型」页签，点「去审核」。左侧逐条列出员工识别出的关系，每条给出关联字段；有的关系还会附取值重合率，或「智能体推断」「用户确认」标签，没有附时按关联字段判断。员工会给实体起业务名称，可能与表名不完全一样，按关联字段判断即可。关系较多时，列表要往下滚动才能看全。按下面的规则逐条点「成立」或「不成立」：

- 订单、仓库可供产品、VMI客户、仓库港口、仓库成本到仓库产能（仓库代码），以及它们到仓库成本（仓库代码）：取值都对得上（仓库可供产品有 1 行的仓库不在产能表里，重合约 99.95%），点「成立」。
- 订单到仓库可供产品，按「仓库代码 + 产品编号」两列相连：每张订单的仓库与产品组合都在可供产品表里，点「成立」。
- 除此之外如果还出现别的关系（例如订单只按仓库代码一列连到仓库港口或仓库可供产品、订单与仓库可供产品只按产品编号一列相连、订单与运费费率按承运商相连、订单与 VMI客户按客户相连、订单的起运港连到仓库港口的港口）：它们不是多对一的对应，点「不成立」。实测中员工把这些小表都挂在订单上，按这条规则只有订单到仓库产能、订单到仓库成本两条成立。

员工识别出的关系条数每次可能略有不同：下方「期望结果」里有、但这次没有出现的关系，不用手动补，跳过即可（首扫成绩会相应扣分）。审核页只确认关系，指标发布后仍是「待确认」（所以第 6 步问数时员工可能先弹卡请你确认口径）。页面下方的「试问」与「待解问题」是员工的自检记录，可以只看不处理。审核时在对话框内部滚动，发布前不要点对话框外的灰色区域（会直接关闭对话框，已点的选择会丢失）。全部处理后点右下角「发布」，看到「实体模型已发布」即完成。

![审核关系](images/6-review.jpg)

### 6. 问数

在资料库顶部点「智能问答」。输入框开头有一个「针对 案例08 仓库停运影响 回答：」的前缀块，先点一下前缀块右侧，再输入问题，按回车发送。逐题输入下方表格里的问题，与标准答案核对。问数由「源宜助理」回答（构筑由「BI 分析师」完成），两者用的是同一个已发布的实体模型。

员工有时会先弹卡请你确认指标口径：确认无误就选中「确认…」或「认可…」这一项，再点「提交并继续」。之后如果弹出「修改实体模型」的授权卡，选「允许一次」。如果弹出的授权卡只有「始终允许」（例如员工想在本机执行脚本），可以点「拒绝」，员工会改用资料库里的表格作答。

## 自行核对

在仓库根目录运行（需要 Python 3.9+ 与 PyYAML）：

```bash
python3 -I tools/casekit.py answers cases/08-supply-disruption --check
```

从原始文件重算标准答案（原始文件的下载方法见 [PROVENANCE.md](../../PROVENANCE.md)）：

```bash
python3 -I cases/08-supply-disruption/prepare/truth_from_raw.py <原始文件路径>
```

把员工的回答逐题存成 `answers/q01.txt` … 后，可以自动判分：

```bash
python3 -I tools/casekit.py grade cases/08-supply-disruption answers
```

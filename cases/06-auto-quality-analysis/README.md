# 案例 06 · 整车召回分析（复现 Malloy 官方演示）

> **数据档位：真实测量**。数据是美国国家公路交通安全管理局（NHTSA）的真实召回记录，取自 Google Malloy 官方样例仓库 malloydata/malloy-samples 的 auto_recalls 演示（MIT 许可；底层为美国联邦政府公有领域数据）；本仓库只取 2021 年起的 1,574 条、译了列名，另派生日历、部件、召回类型三张对照表，召回记录一字未改。出处、许可、原始文件 sha256 与复现方法见 [PROVENANCE.md](../../PROVENANCE.md)。

> 场景与问题复现自 Malloy（Google 的开源语义建模语言）官方样例 auto_recalls：<https://github.com/malloydata/malloy-samples/tree/main/auto_recalls>。问答题 q01–q07 的问题意图取自它的语义模型 auto_recalls.malloy（召回数、潜在受影响数量合计、占比三个度量，按厂商、类型、年份、最近召回、最大召回等视图）与 README 里的刹车召回看板，出处逐题写在 questions.yaml 的 source。
> 旧版案例 06 是自建虚构的维修与回访数据，已替换；教程文字、截图均为本仓库自行撰写与拍摄。

## 场景

一家整车或零部件企业的质量部门，要从美国监管机构的召回记录里看行业质量问题：哪些厂商召回最多、潜在受影响车辆有多少、召回集中在哪些部件、整车与设备、轮胎、儿童座椅各占多少、最近和规模最大的召回是什么。Malloy 用这份数据演示了同一套口径的语义模型与看板，本案例用 Yuanease 从表格出发复现它。

## 你将完成

1. 新建资料库并上传 4 张表格。
2. 让数字员工「BI 分析师」构筑实体模型：识别实体、唯一标识列、表与表之间的关系，以及常用指标。
3. 审核员工识别出的关系并发布。
4. 用自然语言问业务问题，与下方标准答案逐题核对。

预计用时 25–35 分钟（构筑 6–12 分钟，问数每题 1–3 分钟）。

数据要点：

- 「召回」一行一条召回，NHTSA 编号唯一（例如 22V444000，V 表示整车、E 设备、T 轮胎、C 儿童座椅）；报告接收日期是原始的「月/日/年」写法；主题、召回描述、后果摘要、纠正措施是英文原文。
- 「潜在受影响数量」是厂商申报的可能受影响的车辆或产品数量，Malloy 模型里叫 total_defects，按它求和就是潜在受影响合计。
- 「部件」「召回类型」两张表给出原始英文取值对应的中文译名（译名由本仓库给出）；「日历」给出每个接收日期的标准写法、年份、月份与季度。
- 本案例只含 2021-01-01 至 2022-06-23 接收的召回（原始数据截止到 2022 年 6 月），Malloy 演示用的是 1966 年以来的全量数据，所以具体数字与 Malloy 的演示截图不同，口径相同。

数据来源与改动：取自 Malloy 官方样例仓库的 auto_recalls/auto_recalls.csv（固定到提交 89eb0fd 的地址见 PROVENANCE.md）；只取 2021 年起的召回，列名译成中文；日历、部件、召回类型三张表由召回表派生。规则见 `prepare/build_data.py` 文件头；`prepare/truth_from_raw.py` 直接从原始 CSV 重算全部标准答案，并核对召回表与原始文件逐行相同。

## 操作步骤

### 0. 准备

- 安装并登录 Yuanease 桌面应用（版本 0.8.7 或更高）。
- 下载本仓库：`git clone <仓库地址>`，或在仓库页面下载 ZIP 后解压。本案例的数据在 `cases/06-auto-quality-analysis/data/`。

### 1. 新建资料库

左侧导航进入「资料库」，点右上角「新建资料库」。名称填「案例06 整车召回」（如果账号里已经有同名资料库，可以在名称后加上日期或姓名缩写以示区分），描述可选填，范围与权限保持默认，点「创建资料库」。

![新建资料库](images/1-new-kb.jpg)

### 2. 上传表格

在新资料库里点右上角「添加」→「表格」，点「点击上传、拖拽或粘贴文件」，选中 `data/` 目录下全部 4 个文件（选文件前主按钮叫「开始索引」且不可点，选中后变成「索引 4 个文件」），点它。之后对话框会回到空的上传状态，这是正常的：关掉对话框，资料库的内容列表里每个文件显示「就绪」（通常 10–60 秒）即完成；页面上的构筑提示写的表格数会随就绪逐步增加，等它与上传的文件数一致再进入下一步。如果账号里有同名资料库或同名线程，请从资料库列表的卡片进入自己建的那个。

![选择表格](images/2-upload.jpg)

### 3. 构筑实体模型

切到「实体模型」页签，点「构筑实体模型」。向导默认选中全部表格，保存位置为新建文件夹「实体模型」，由「BI 分析师」构筑。保持默认，点「开始构筑」。

![构筑向导](images/3-build-wizard.jpg)

构筑在后台运行，可以关掉窗口。进度窗口可能较长时间停在「解析表格」，属正常现象。

- 页头右侧的「● 1」可以打开「智能体工位」，查看这次构筑的进度；
- 回到「实体模型」页签时，如果看到「有一次构筑还没完成。」和「继续构筑」按钮，点它只是重新打开这次构筑的进度窗口，不会重新开始。

![构筑进行中](images/4-build-running.jpg)

### 4. 回答员工的提问

开始几分钟后，员工会把从数据里看不出业务含义的地方集中问你一次（问题内容每次可能不同）。提问卡片「数字员工需要你的输入」在页头「● 1」打开的「智能体工位」里（标着「需人工」的卡片，状态为「待输入」或「等待输入」，点开即可），也可以从左侧线程里标着「待输入」的这次构筑进入；构筑进度窗口变成「员工在等你处理」时，窗口里的「查看过程」按钮也能直接进入。**不回答，构筑会一直停着。**了解业务就直接回答，可以参考上方「数据要点」；不确定就回答「不知道，请你按数据自己判断。」，本案例的实测成绩按这个回答得到；独立复现或想与实测成绩对比时，统一这样回答。填好后点「提交并继续」。

（实测后补：员工这次问了什么、怎样回答。）

![员工提问](images/5-employee-question.jpg)

如果希望员工一次建得更完整，可以把下面这段参考回答整段粘贴进去（它说明了本案例的业务含义与常用指标口径；本页「实测记录」的首扫成绩是在不提供这段说明的情况下得到的）：

> 召回一行一条召回，NHTSA 编号唯一；报告接收日期关联日历表得到年份、月份、季度；部件、召回类型关联各自的对照表得到中文名。常看：召回数（计数）、潜在受影响数量合计（求和）、各组召回占全部召回的百分比。

### 5. 审核关系并发布

构筑完成后，回到资料库的「实体模型」页签，点「去审核」。左侧逐条列出员工识别出的关系，每条给出关联字段；有的关系还会附取值重合率，或「智能体推断」「用户确认」标签，没有附时按关联字段判断。员工会给实体起业务名称，可能与表名不完全一样，按关联字段判断即可。关系较多时，列表要往下滚动才能看全。按下面的规则逐条点「成立」或「不成立」：

- 召回到日历（报告接收日期 = 日期）、召回到部件（部件）、召回到召回类型（召回类型）：取值都 100% 对得上，点「成立」。
- 除此之外如果还出现别的关系：本案例没有其他对应，点「不成立」。

员工识别出的关系条数每次可能略有不同：下方「期望结果」里有、但这次没有出现的关系，不用手动补，跳过即可（首扫成绩会相应扣分）。审核页只确认关系，指标发布后仍是「待确认」（所以第 6 步问数时员工可能先弹卡请你确认口径）。页面下方的「试问」与「待解问题」是员工的自检记录，可以只看不处理。审核时在对话框内部滚动，发布前不要点对话框外的灰色区域（会直接关闭对话框，已点的选择会丢失）。全部处理后点右下角「发布」，看到「实体模型已发布」即完成。

![审核关系](images/6-review.jpg)

![发布完成](images/7-published.jpg)

### 6. 问数

在资料库顶部点「智能问答」。输入框开头有一个「针对 案例06 整车召回 回答：」的前缀块，先点一下前缀块右侧，再输入问题，按回车发送。逐题输入下方表格里的问题，与标准答案核对。问数由「源宜助理」回答（构筑由「BI 分析师」完成），两者用的是同一个已发布的实体模型。

员工有时会先弹卡请你确认指标口径：确认无误就选中「确认…」或「认可…」这一项，再点「提交并继续」。之后如果弹出「修改实体模型」的授权卡，选「允许一次」。如果弹出的授权卡只有「始终允许」（例如员工想在本机执行脚本），可以点「拒绝」，员工会改用资料库里的表格作答。

## 自行核对

在仓库根目录运行（需要 Python 3.9+ 与 PyYAML）：

```bash
python3 -I tools/casekit.py answers cases/06-auto-quality-analysis --check
```

从原始文件重算标准答案（原始文件的下载方法见 [PROVENANCE.md](../../PROVENANCE.md)）：

```bash
python3 -I cases/06-auto-quality-analysis/prepare/truth_from_raw.py <原始文件路径>
```

把员工的回答逐题存成 `answers/q01.txt` … 后，可以自动判分：

```bash
python3 -I tools/casekit.py grade cases/06-auto-quality-analysis answers
```

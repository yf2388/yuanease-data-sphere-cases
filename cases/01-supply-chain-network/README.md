# 案例 01 · 多工厂供应链：库存、物料清单与订单

> **数据档位：厂商样例**。数据是 Snowflake 为教程公开发布的样例库（公司与数据为虚构，但出自第三方、不是本仓库编的），本仓库只译了表名列名、改写了布尔与时间格式，取值未改。出处、许可、原始文件 sha256 与复现方法见 [PROVENANCE.md](../../PROVENANCE.md)。

> 场景参考自 Snowflake 的公开教程「Build a Supply Chain Assistant with Snowflake Intelligence」（<https://snowflake.com/en/developers/guides/snowflake-agentic-ai-in-supply-chain/>）。
> 本案例只复现其业务场景与问题；数据来自该教程仓库（MIT 许可），表名与列名已译为中文；教程文字、截图均为本仓库自行撰写与拍摄。

## 场景

一家多事业部的工业制造企业（航空航天、工业自动化、建筑系统、能源四条业务线）在美国有 24 家工厂。运营经理每天要回答这些问题：哪些工厂的原材料库存偏低、成品还有多少、哪些客户贡献了最多订单金额、发货是否准时。

数据分散在 11 张表里：主数据（供应商、原材料、零部件、产品、工厂、客户）、结构数据（物料清单、厂间运输附加费）和业务数据（工厂库存、订单、发货）。本案例演示如何用 Yuanease 的「实体模型」把这些表整理成统一的业务口径，再用自然语言直接问数。

## 你将完成

1. 新建资料库并上传 11 张表格。
2. 让数字员工「BI 分析师」构筑实体模型：识别实体、唯一标识列、表与表之间的关系，以及常用指标。
3. 审核员工识别出的关系并发布。
4. 用自然语言问业务问题，与下方标准答案逐题核对。

预计用时 30–40 分钟（构筑 8–15 分钟，问数每题 1–3 分钟）。

数据要点：

- 「物料清单」的「父产品编号」列里既有产品编号（5001–8010），也有零部件编号（1001–4014），表示子装配的父项；「父零部件编号」列在数据里全空。
- 「零部件」的「关联物料清单」列与物料清单编号没有任何重合，约 77% 的取值能对上产品编号，源数据没有说明它的含义。
- 「工厂库存」的一行是「某工厂的某一种库存物料」，原材料编号、零部件编号、产品编号三列中只有一列有值，因此需要四列组合才能唯一定位一行。
- 金额没有币种，回答里的币种符号以原数据为准。

数据来源与改动：取自 Snowflake-Labs/sfguide-supply-chain-assistant-with-snowflake-intelligence 仓库 `scripts/setup.sql` 中的 INSERT 数据；表名、列名译为中文；布尔值写成「是/否」；时间戳去掉时区后缀；不含天气表。原指南建库时会用 UPDATE 把订单、发货等日期平移到安装当天附近，本案例保留 INSERT 里的原始日期。重新生成方法见 `prepare/build_data.py` 文件头。

## 操作步骤

### 0. 准备

- 安装并登录 Yuanease 桌面应用（版本 0.8.7 或更高）。
- 下载本仓库：`git clone <仓库地址>`，或在仓库页面下载 ZIP 后解压。本案例的数据在 `cases/01-supply-chain-network/data/`。

### 1. 新建资料库

左侧导航进入「资料库」，点右上角「新建资料库」。名称填「案例01 多工厂供应链」（如果账号里已经有同名资料库，可以在名称后加上日期或姓名缩写以示区分），描述可选填，范围与权限保持默认，点「创建资料库」。

![新建资料库](images/1-new-kb.jpg)

### 2. 上传表格

在新资料库里点右上角「添加」→「表格」，点「点击上传、拖拽或粘贴文件」，选中 `data/` 目录下全部 11 个文件，再点「索引 11 个文件」。之后对话框会回到空的上传状态，这是正常的：关掉对话框，资料库的内容列表里每个文件显示「就绪」（通常 10–60 秒）即完成；页面上的构筑提示写的表格数会随就绪逐步增加，等它与上传的文件数一致再进入下一步。如果账号里有同名资料库或同名线程，请从资料库列表的卡片进入自己建的那个。

![选择表格](images/2-upload.jpg)

### 3. 构筑实体模型

切到「实体模型」页签，点「构筑实体模型」。向导默认选中全部表格，保存位置为新建文件夹「实体模型」，由「BI 分析师」构筑。保持默认，点「开始构筑」。

![构筑向导](images/3-build-wizard.jpg)

构筑在后台运行，通常需要 8–15 分钟，可以关掉窗口。进度窗口可能较长时间停在「解析表格」，属正常现象。

- 页头右侧的「● 1」可以打开「智能体工位」，查看这次构筑的进度；
- 回到「实体模型」页签时，如果看到「有一次构筑还没完成。」和「继续构筑」按钮，点它只是重新打开这次构筑的进度窗口，不会重新开始。

![构筑进行中](images/4-build-running.jpg)

### 4. 回答员工的提问

开始几分钟后，员工会把从数据里看不出业务含义的地方集中问你一次（问题内容每次可能不同）。提问卡片「数字员工需要你的输入」在页头「● 1」打开的「智能体工位」里（标着「需人工」的卡片，旁边写着员工要你确认的内容，状态为「待输入」或「等待输入」，点开即可），也可以从左侧线程里标着「待输入」的这次构筑进入。**不回答，构筑会一直停着。**了解业务就直接回答，可以参考上方「数据要点」；不确定就回答「不知道，请你按数据自己判断。」，本案例的实测成绩按这个回答得到；独立复现或想与实测成绩对比时，统一这样回答。填好后点「提交并继续」。构筑进度窗口变成「员工在等你处理」时，窗口里的「查看过程」按钮也能直接进入提问卡片。

实测中员工问过的内容包括：工厂库存一行代表什么、物料清单的父项列、「关联物料清单」指向哪张表、订单状态的含义、发货与订单是否关联。了解业务时可以这样回答：「工厂库存一行是某工厂的一种库存物料，三个物料编号列只有一列有值；物料清单的父产品编号是父项，可以是产品也可以是零部件；关联物料清单的含义不清楚。」

![员工提问](images/5-employee-question.jpg)

如果希望员工一次建得更完整，可以把下面这段参考回答整段粘贴进去（它说明了本案例的业务含义与常用指标口径；本页「实测记录」的首扫成绩是在不提供这段说明的情况下得到的）：

> 这是多工厂制造企业的供应链数据。工厂库存一行是某工厂的一种库存物料，原材料编号、零部件编号、产品编号三列中只有一列有值；物料清单一行是父项对一条子项的用料，父产品编号可能是产品也可能是零部件；零部件的「关联物料清单」含义不明，不要用它关联。订单状态 Placed、In Production、Shipped、Delivered 依次是已下单、生产中、已发货、已签收；发货与订单没有直接关联。常用指标：订单数（订单计数）、订单金额（订单金额合计）、在产工厂数（是否在产 = 是 的工厂计数）、成品在库数量（产品编号非空的在库数量合计）。

### 5. 审核关系并发布

构筑完成后，回到资料库的「实体模型」页签，点「去审核」。左侧逐条列出员工识别出的关系，每条给出关联字段；有的关系还会附取值重合率，或「智能体推断」「用户确认」（第 4 步里你确认过的）标签，没有附时按关联字段判断，默认都是「暂不确定」。员工会给实体起业务名称，可能与表名不完全一样（例如「货运」显示为「货运单」），按关联字段判断即可。关系较多时，列表要往下滚动才能看全。按下面的规则逐条点「成立」或「不成立」：

- 取值重合 100% 的关系：点「成立」。
- 物料清单的「父产品编号 = 产品编号」与「父产品编号 = 零部件编号」（重合率低于 100%）：点「成立」，原因见上方数据要点（两条中出现哪条就处理哪条）。
- 「零部件 · 关联物料清单 = 产品编号」（重合率约 77%）：源数据没有这条关联，点「不成立」。
- 其他字段名称明显对应的关系：点「成立」。

员工识别出的关系条数每次可能略有不同：下方「期望结果」里有、但这次没有出现的关系，不用手动补，跳过即可（首扫成绩会相应扣分）。审核页只确认关系，指标发布后仍是「待确认」（所以第 6 步问数时员工可能先弹卡请你确认口径，再申请把确认写回实体模型）；员工起草的指标目前以计数类为主，「期望结果」里的合计、比率类指标可能没有生成，这不影响后面问数（员工会按原始表计算并说明口径）。页面下方的「试问」与「待解问题」是员工的自检记录，可以只看不处理。审核时在对话框内部滚动，发布前不要点对话框外的灰色区域（会直接关闭对话框，已点的选择会丢失）。全部处理后点右下角「发布」，看到「实体模型已发布」即完成。如果发布后发现有关系没确认，可以在「实体模型」页签切到「实体」，点开实体，在右侧「关系」页签里逐条点「确认」或「不成立」。

![审核关系](images/6-review.jpg)

![发布完成](images/7-published.jpg)

### 6. 问数

在资料库顶部点「智能问答」。输入框开头有一个「针对 案例01 多工厂供应链 回答：」的前缀块，先点一下前缀块右侧，再输入问题，按回车发送。会话页头的「未选择目录」提示不影响问数，可以忽略。逐题输入下方表格里的问题，与标准答案核对。问数由「源宜助理」回答（构筑由「BI 分析师」完成），两者用的是同一个已发布的实体模型。

员工有时（不是每次）会先弹卡请你确认指标口径（例如「订单数 = 按行计数」）：确认无误就选中「确认…」或「认可…」这一项，再点「提交并继续」。之后如果弹出「修改实体模型」的授权卡（员工要把你的确认写回模型），选「允许一次」。如果弹出的授权卡只有「始终允许」（例如员工想在本机执行脚本），可以点「拒绝」，员工会改用资料库里的表格作答。如果弹出要在本机运行命令（例如查找文件）的授权卡，问数并不需要它：点「允许一次」或「拒绝」都可以，拒绝后员工同样会改用资料库里的表格。
